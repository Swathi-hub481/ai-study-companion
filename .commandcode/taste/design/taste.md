# Design

- Wants a premium, restrained "serious SaaS/EdTech" look built from first principles: generous whitespace, strong visual hierarchy, excellent typography, subtle borders, restrained shadows, polished cards, consistent spacing, rounded-but-not-pill components. The product should look expensive through design quality, not visual effects. Confidence: 0.7
- Explicitly rejects overdesign: excessive gradients, glassmorphism-heavy surfaces, neon/glow effects, heavy or distracting animation, particle effects, huge decorative illustrations, emoji-heavy UI, clutter, random colours, generic template-looking layouts, and fake statistics/notifications/content invented from a mockup. Confidence: 0.75
- Defines a design system before redesigning individual pages: semantic tokens for colour/typography/spacing/radius/border/shadow that components reference rather than ad-hoc values, a single accent family, and an explicit hierarchy for primary/secondary/tertiary/destructive actions and info/success/warning/error states. Confidence: 0.7
- Wants micro-interactions subtle and fast (button/card hover, navigation transition, skeleton shimmer, progress transition, dialog entrance), with `prefers-reduced-motion` respected, and prefers CSS/Tailwind over JavaScript or animation libraries for simple effects. Confidence: 0.6
- Requires every major screen to have intentional loading, empty, error, and success states — skeletons that match the layout that is coming, empty states that explain the next action, errors that say what went wrong and how to recover — never blank sections. Confidence: 0.6
- For redesign work on an existing app, wants the reference's desktop composition preserved and responsiveness achieved by reusing the app's existing responsive patterns — do not break mobile layouts and do not introduce a completely different mobile design. Confidence: 0.5
- Requires responsive design across a wide breakpoint range (1440px down to 375px) with genuine mobile adaptations — drawer/off-canvas navigation rather than a shrunk sidebar, a thumb-reachable bottom navigation bar on phones, stacked cards and stat tiles, usable tables, thumb-friendly quiz controls, full-width chat, and geometry that respects device safe-area (notch/home-indicator) insets so content is never trapped under a fixed bar — and no horizontal page overflow. Confidence: 0.65
- Expects the page skeleton to be structurally identical across the whole app: the `<h1>` page title first with the section/tab nav beneath it on every page, and headings, subtitles and table treatments drawn from one shared convention — a section nav sitting above the title, a page using a different subtitle/ink token, or a table drawing divider rules while others do not reads as a defect to be fixed. Confidence: 0.55
- Wants learning data presented honestly: mastery shown as an estimate without misleading precision, growth stated factually, and learner progress never exaggerated. Confidence: 0.65
- Treats a supplied reference image as a strict specification to reproduce, not as direction or "inspiration": the actual layouts, compositions, proportions, colours, spacing, typography hierarchy and component arrangement are the target, a different section arrangement must not be substituted for the reference's (e.g. keep the reference dashboard's greeting → stat row → continue-learning cards → recent activity → quick actions order), and structural rework is preferred over polishing the existing implementation when the two disagree. Fidelity to the reference outranks generic quality — "do not stop merely because the page looks professional", and this still holds after a design system has already been built from the same reference. Distinctive elements of the reference must survive even when they cut against the surrounding theme (a light/white authentication card on a dark branded panel stays light rather than being turned into a dark form). Confidence: 0.85
- When a brief or an attached reference image sets the direction, treats it as the primary visual source of truth and wants that design language reproduced consistently across every page so the whole product reads as one cohesive application — matching spacing, proportions, typography, card dimensions, sidebar width, border radius, border opacity, control height, icon size, alignment, colours, gradients, shadows, progress bars, badges, tabs and input styling. For a dark direction that means a premium modern-learning-SaaS look (deep navy canvas, slightly raised near-navy cards with thin translucent borders and rounded corners, violet/indigo primary actions, cyan/teal secondary accents, green/amber/red reserved for state, subtle glow, compact dashboard grids) rather than a generic Bootstrap or light SaaS template. Confidence: 0.7
