# Code Quality

- Rejects shortcuts that merely make a test pass: do not weaken or remove safety gates (e.g. the evidence gate), do not hardcode expected answers, do not bypass the real mechanism (e.g. pgvector retrieval), do not drop isolation, and do not weaken, skip, or delete tests to get the suite green. Demands the actual root-cause bug be found and fixed. Confidence: 0.85
- When several components/forms share the same underlying pattern and exhibit the same defect, wants the shared root cause fixed once rather than duplicating an identical fix per instance — and where the implementations genuinely differ, each is fixed minimally in place. Confidence: 0.6
- Prefers small, minimal, reversible changes over large rewrites — for bug fixes, optimizations, and other non-feature work alike; large refactors or redesigns are unwanted. Confidence: 0.75
- Secrets (API keys, tokens, credentials) must never be printed or logged; report only whether a credential is present/non-empty, and redact anything that could resemble a credential in diagnostic output or telemetry. Confidence: 0.85
- Prefers pure, dependency-free domain logic (e.g. policy/derivation modules such as mastery, selection, and grading) that is unit-testable in isolation and safely importable by both services and UI, rather than logic coupled to Prisma or the AI layer. Confidence: 0.6
- Prefers avoiding new heavyweight dependencies in favour of small hand-rolled solutions: repeatedly chose server-rendered inline SVG over installing a charting library (recharts) — a sparkline in one phase, then a heatmap and radar in the next, even when the charting library was already named in the plan; wants charts that render server-side with no client-side chart dependency. Confidence: 0.75
- Prefers fail-loud over silent degradation: an unsafe or unsupported operation should raise a clear, actionable error rather than quietly doing the wrong thing (seeding refuses to create a known-password admin in production; `STORAGE_DRIVER=s3` throws instead of writing to ephemeral disk; no silent provider fallback). Confidence: 0.6
- Treats accessibility and complete UI states as required work rather than polish: labelled form controls, real table semantics (caption + `scope`), `aria-live` for streamed content, plus error, global-error, not-found, and loading boundaries instead of relying on framework defaults. Confidence: 0.65
- Treats accessibility as non-negotiable and superior to visual fidelity: for every state touched, keyboard access, visible focus states, appropriate ARIA, readable contrast and semantic headings/buttons/links must be preserved, and colour must never be the sole carrier of meaning — "do not sacrifice accessibility for visual similarity". Confidence: 0.65
- Prefers cross-cutting policy centralised in a single exported table with tests (e.g. one `RATE_LIMITS` map) rather than the same constants duplicated as literals across call sites. Confidence: 0.5
- When doing UI/presentation work, treats the backend as off-limits: no changes to routes, API contracts, database schema, Prisma models, prompts, retrieval thresholds, or learning/grading/mastery/analytics algorithms, and no rewriting backend logic just to make the frontend easier. Wants the project inspected before anything is modified, with changes confined to app pages, components, Tailwind/CSS and existing visual components and kept out of `lib/ai`, `lib/rag`, `lib/services`, `lib/jobs`, Prisma schema, API routes, auth services, the worker, telemetry and performance utilities; if a non-UI file genuinely must change, stop and explain why first rather than changing it silently. Confidence: 0.8
- When a UI section needs data the backend does not already supply, prefers the section be omitted outright rather than enabling it with any backend change: no new query, no new endpoint, no schema change, no extra network request — a single read-only `findMany` added to an existing `Promise.all` purely for a visual "Recent Activity" section had to be reverted and the section dropped, and existing data-fetching behaviour kept byte-for-byte intact. Present the reference composition minus the unsupported part rather than bending the data layer. Confidence: 0.8
- Where a UI needs data or capability the backend does not provide, wants the gap reported rather than filled in: no fake or placeholder UI, no mocks replacing working functionality, no invented data or backend behaviour, and no unsupported product claims in marketing copy — including display-only details, where fabricated processing percentages, sources, citations, system-health status, or any metric the data model does not produce must be replaced by the real field. Confidence: 0.8
- Wants components de-duplicated rather than copy-pasted — inspect existing components before writing new ones and extract shared ones where repetition is genuine (PageHeader, StatCard, StatusBadge, EmptyState, …) — but explicitly avoids over-engineering. Confidence: 0.6
- Prefers server-rendered components with minimal client-side JavaScript, CSS/Tailwind for simple effects, and no unnecessary dependencies or duplicated data fetching, and treats this as a frozen constraint during UI work: no duplicate API requests or data fetching, no unnecessary `useEffect`/polling/refetch-on-render, no expensive client-side computation, no avoidable Server→Client conversions or hydration, no heavy animation/image libraries, no layout thrashing, and no moving existing server-side fetching to the client — style the data a page already has instead of adding endpoints or fake loading states. Confidence: 0.8
- Demands evidence over assertion on performance: measure a baseline before changing anything, never guess at bottlenecks, prove improvements with before/after numbers, and do not present a difference that falls inside the run-to-run noise band as a win — "do not claim improvements without measurement", "do not stop at 'the code looks faster'". Confidence: 0.85
- Will not accept a speed-up won by cheating: no fake/mocked responses or cached fake answers in production paths, no artificial delays or simulated streaming, no lowered retrieval, context, or quiz quality, no removed evidence checks, telemetry, or security checks, and no hiding slow work instead of fixing it. Confidence: 0.7
